# EchoMind 简历包装指南

本文档用于把 EchoMind 项目包装成简历、面试和项目展示中可讲清楚的经历。建议按真实实现描述，量化数据如果没有压测或标注集支撑，应写成“设计目标”或“在内置评测集上”。

## 三段式项目描述

### 项目背景

SaaS 企业的客户交付、技术支持、客户成功和续费运营团队每天都会处理大量跨领域业务问题，例如客户上线计划、API/Webhook 集成异常、SLA 影响评估、功能采用率下降和续费风险判断。传统方式依赖员工分别查阅产品文档、排障手册和运营数据，再人工汇总结论，容易出现知识分散、问题误分流和复合问题只处理一部分等问题。

我设计并实现了 **EchoMind SaaS 客户运营与交付多 Agent 分析平台**。它面向 SaaS 企业内部员工，围绕客户项目、服务问题和客户经营问题提供知识增强问答、原因分析、风险判断和行动建议。系统不直接执行生产变更，而是输出带证据、风险和后续建议的可审阅分析结果。

### 核心方案

- **两层意图识别**：将客户运营问题拆分为 19 个细粒度意图，例如 `integration_webhook`、`reliability_sla`、`success_health` 和 `renewal_risk`，再归并到 `implementation`、`integration`、`reliability`、`entitlement`、`adoption`、`escalation` 六个意图组；结合 LLM 语义理解、Embedding 相似度和关键词 Pattern 加权投票，输出意图、意图组、置信度、紧急度和结构化实体。
- **多 Agent 专业协作**：通过 `TriageAgent` 进行分诊和结果汇总，由 `DeliveryAgent`、`SupportAgent`、`SuccessAgent`、`RenewalAgent` 分别处理交付实施、技术支持、客户成功和续费运营分析；根据领域分数和跨域关键词选择主 Agent 与辅助 Agent，复杂问题并行分析后合并结果。
- **知识增强与动态规则**：以虚构的企业数据集成产品 FlowForge Cloud 为统一业务背景，使用 ChromaDB 构建实施、集成排障、可靠性/SLA、客户健康度和续费运营知识库；通过 Markdown Skills 按 Agent 类型和关键词动态注入领域分析规范，支持运行时热加载。
- **记忆、治理与可观测性**：使用 Redis 保存会话工作记忆，ChromaDB 保存历史摘要和用户画像；MCP 工具层提供查询改写、并行召回、重排、缓存、超时、熔断和 fallback；Monitor 持续采集 Agent/工具成功率与延迟，并将表现反馈到后续路由评分。

### 实验验证

- **细粒度路由验证**：为 19 个业务意图准备内置评测样例，覆盖实施计划、环境配置、数据迁移、Webhook、SSO、数据同步、故障影响、SLA、客户健康度、配额和续费准备等场景；通过 Pattern 识别和意图组完整性检查，确认 19 个意图均能映射到六个意图组。
- **多 Agent 协作验证**：使用“Webhook 返回 401、客户无法上线且临近续费”等复合请求验证路由，系统选择 `SupportAgent` 为主 Agent，并协作 `DeliveryAgent` 和 `RenewalAgent`，最终汇总技术原因、交付阻塞和续费风险。
- **知识库与 Skills 验证**：启动时检查默认 FlowForge Cloud 知识库文档是否可加载，验证五类 Skills 的 front matter、Agent 匹配和关键词注入；当前五类 Skills 均加载成功且解析错误为 0。
- **工程质量验证**：对核心 Python 模块执行 `py_compile` 和 `git diff --check`，并通过本地路由、Pattern 识别和 Skill 加载检查。真实 LLM 端到端效果需要在安装 `anthropic` 依赖并配置 API 后，通过 `/eval/run` 和实际模型调用继续验证。

### Q6：端到端 Agent 怎么评测？

**回答思路**

评测分两部分：

1. 意图识别评测：用标注用例计算 Accuracy 和 Macro-F1。
2. 端到端回复评测：真实调用 `Orchestrator.run()` 生成回复，再用 LLM-as-Judge 从四个维度打分。

四个维度是：

- `relevance`：是否回答用户问题。
- `accuracy`：信息是否准确。
- `completeness`：是否完整解决需求。
- `helpfulness`：用户能否据此行动。

评测器还会和上一轮结果对比，如果某个指标退化超过 5%，会标记为 regression，并生成优化建议。

## 30 秒项目 Pitch

> EchoMind 是一个面向 SaaS 客户交付与运营问题的多 Agent 问答与分析运行时。我主要解决了七个工程问题：第一，意图识别用 LLM、Embedding 和 Pattern 三路融合，输出细粒度 intent、intent_group、来源分数和结构化实体；第二，知识库检索按意图触发，使用查询改写、并行召回和 LLM 重排增强业务分析；第三，通过动态 Skills 把交付、技术支持、客户成功和续费运营分析规范按 Agent 类型注入 prompt；第四，多轮对话用异步 Redis 工作记忆、ChromaDB 情景记忆和用户画像管理上下文；第五，多 Agent 通过 RoutingDecision 生成 primary_agent、supporting_agents 和 routing_reason，支持复合问题主辅协作；第六，Monitor 会根据成功率和延迟写回降权因子，动态影响后续路由；第七，用 LLM-as-Judge 做端到端评测和回归检测。整个系统可以用 Docker Compose 一键启动。
