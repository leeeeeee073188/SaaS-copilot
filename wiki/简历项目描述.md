# EchoMind 简历项目描述

## 项目名称

**EchoMind SaaS 客户运营与交付多 Agent 分析平台**

技术栈：Python、FastAPI、DeepSeek Compatible API、Redis、ChromaDB、Docker、Prometheus

## 项目背景

SaaS 企业内部的客户交付、技术支持、客户成功和续费运营团队，持续面对客户上线计划、API/Webhook 集成异常、SLA 影响评估、功能采用率下降和续费风险判断等问题。传统处理方式依赖员工分别查阅产品文档、排障手册和运营数据，再手工汇总结论，容易出现知识分散、问题误分流，以及复合问题只处理单一方面的问题。

针对这一场景，我设计并实现了 EchoMind：一个面向 SaaS 企业内部员工的问答与分析型多 Agent 平台。系统围绕客户项目、服务问题和客户经营信息，提供知识增强问答、原因分析、风险判断和后续建议，不直接执行生产变更或替代企业权限系统。项目以虚构的企业数据集成产品 FlowForge Cloud 作为统一业务背景，保证不同分析任务具有一致的产品语境。

## 核心方案

### 1. 细粒度意图识别与结构化路由

- 将业务请求拆分为 19 个细粒度意图，覆盖实施计划、环境准备、数据迁移、上线验收、API、Webhook、SSO、数据同步、故障事件、性能、SLA、套餐权益、配额、功能采用、客户健康度、续费风险、续费准备和升级风险等场景。
- 将 19 个意图归并到 `implementation`、`integration`、`reliability`、`entitlement`、`adoption`、`escalation` 六个意图组，输出 `intent`、`intent_group`、`confidence`、`urgency`、`source_scores` 和结构化实体。
- 使用 LLM Few-shot、Embedding 相似度和关键词 Pattern 三路融合，通过加权投票兼顾语义理解、相似表达匹配和低延迟规则兜底。

### 2. 多 Agent 专业协作

- 通过 `TriageAgent` 负责问题分诊、主辅 Agent 选择和结果汇总。
- 由 `DeliveryAgent`、`SupportAgent`、`SuccessAgent`、`RenewalAgent` 分别处理客户交付、技术支持、客户成功和续费运营分析。
- 根据意图、关键词和实体计算领域分数，生成 `primary_agent`、`supporting_agents`、`routing_reason` 和 `routing_confidence`。
- 对“Webhook 失败 + 客户无法上线 + 续费临近”等复合问题并行调用多个专业 Agent，再合并为统一结论、风险排序和建议行动。

### 3. RAG、记忆与动态业务规则

- 使用 ChromaDB 构建 FlowForge Cloud 知识库，覆盖上线实施、集成排障、可靠性/SLA、客户健康度和续费准备度。
- 在 `/chat` 链路中先识别意图，再通过查询改写、多子查询并行召回、去重和重排获取相关知识，减少无效检索和无依据回答。
- 使用 Redis 保存会话工作记忆，使用 ChromaDB 保存历史摘要和用户画像，支持上下文压缩和异步向量库访问。
- 将交付、支持、客户成功和续费运营规范拆分为 Markdown Skills，按 Agent 类型和关键词动态注入 system prompt，并支持 `/skills/reload` 热加载。

### 4. 工具治理与在线观测

- 在 MCP 工具层增加参数校验、TTL 缓存、超时、熔断和 fallback，提升知识检索链路的稳定性。
- Monitor 采集 Agent/工具成功率、平均延迟和路由评分，通过 `monitor_penalty` 将在线表现反馈给后续 Agent 选择。

## 实验验证

### 1. 意图识别评测

- 使用 `IntentEvaluator` 对标注用例执行完整的意图识别流程，而不是只测试单一 Pattern。
- 以人工标注的 `expected_intent` 作为 gold label，逐条对比预测结果，计算整体 Accuracy、Macro-F1，以及每个意图的 Precision、Recall 和 F1。
- 当前评测集覆盖 19 个业务细粒度意图；评测结果同时记录置信度、推理理由和预测明细，便于定位低 F1 类别并补充 Few-shot 样例。
- 简历中的效果数字应填写实际 `/eval/run` 报告结果：`Accuracy = [待填]`，`Macro-F1 = [待填]`。模板中的 91.3% 和 0.89 不能在没有对应标注集与运行报告时直接使用。

### 2. 端到端回复评测

- 端到端评测真实调用 `Orchestrator.run()`，覆盖单轮和多轮对话，验证记忆读取、意图识别、RAG、Skills 注入、Agent 路由和回复生成是否能够完整串联。
- 使用 LLM-as-Judge 从 `relevance`、`accuracy`、`completeness`、`helpfulness` 四个维度对回复评分，并计算各维度平均分和整体通过率。
- 内置 5 组业务对话用例，覆盖新客户上线、Webhook/SSO 集成故障、SLA 风险、客户健康度和续费准备等场景；单条结果通过阈值为 `0.75`。
- 评测器保存历史基线，当任一指标相对上一轮退化超过 `5%` 时标记 regression，并生成针对意图样例、Prompt 或 RAG 链路的优化建议。

### 3. 当前可核验结果

- 19 个细粒度意图全部完成到 6 个意图组的映射，映射缺失数为 0。
- 复杂复合请求可将 `SupportAgent` 作为主 Agent，并协作 `DeliveryAgent` 和 `RenewalAgent`。
- 五类 Skills 均可加载，解析错误数为 0。
- 核心 Python 模块通过 `py_compile`，代码差异通过 `git diff --check`。
